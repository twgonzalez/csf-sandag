# Data journal

Dated, frozen snapshots of the project's milestone pages — the graphic record of what was known,
claimed, and shown at each point in time.

## Why this exists, next to `reports/`

The two directories answer different questions and must not be confused:

| | `reports/` | `journal/` |
|---|---|---|
| Question | What does the pipeline say **now**? | What did we say **then**? |
| Committed to git | No — regenerated by `make` | **Yes** — the whole point |
| May change | Every run | **Never** — append-only |
| Trust basis | Recomputable from checksummed inputs | Frozen at a named commit |

Reports are reproducible current state. The journal is history. A report that changes is the
pipeline working; a journal entry that changes is a record being rewritten, which is the one
thing a record must never do.

## Conventions

1. **Append-only.** An entry is never edited after its commit. A correction is a *new* entry
   that names what it corrects. (The one exception: fixing a broken link or typo the same day,
   before anything downstream cites the entry.)
2. **Named by date and subject:** `YYYY-MM-DD-slug.html` (or `.md`).
3. **Commit-stamped.** The index below records the repository commit each entry describes, so
   any claim in any entry can be re-verified by checking out that commit and running `make all`.
4. **Self-contained.** Entries are single HTML files with no external assets (Google Fonts
   excepted), so they open in a browser from a file:// path years from now.
5. Published artifact URLs are recorded when they exist, but **the file in this directory is the
   record** — the claude.ai page is a live view that gets overwritten on republish.

## How to review progress later

Open any entry directly in a browser:

```bash
open journal/2026-08-28-progress-ledger.html
```

Or list the arc of the project:

```bash
ls journal/*.html
```
